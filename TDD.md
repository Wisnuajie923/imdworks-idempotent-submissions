# TDD evidence index

Contributor: **enueex** — https://x.com/AjaPawang.

All logs below are subprocess captures, not simulated output. `capture_tdd.py` invokes one selected test, writes stdout/stderr and `EXIT_CODE`, and appends the underlying result to `tdd_logs/cycles.jsonl`. Its own exit status is 0 when the requested phase has the expected result: RED requires a nonzero test exit; GREEN requires zero. Run tests with `python3 run_tests.py`; do not regenerate historical RED evidence against the fixed service or overwrite original logs.

Current `service.py`, `run_tests.py`, and `capture_tdd.py` are the executable source of truth.

## Added vertical slices

### 08 — Strict submission request contract

1. Added `test_08_request_schema` and a traced raw HTTP helper before changing the service.
2. Executed `python3 capture_tdd.py RED test_08_request_schema`: underlying **exit 1**, 28 assertion failures (27 rejected-input subcases plus unchanged-state assertion). Evidence includes an unknown action being treated like create/existence handling, boolean version being accepted and advancing state, and array/null inputs disconnecting instead of returning 400.
3. Implemented only the bounded exact-field/action/string/version contract and shared JSON response helper.
4. Executed `python3 capture_tdd.py GREEN test_08_request_schema`: underlying **exit 0**.

Evidence: `tdd_logs/test_08_request_schema-RED.log`, `tdd_logs/test_08_request_schema-GREEN.log`. The test covers 27 invalid cases, verifies no saved replies/mutations for them, and verifies maximum string bounds are accepted.

### 09 — Deterministic HTTP envelope rejection

1. After slice 08 was GREEN, added `test_09_http_envelope` before its service implementation.
2. Executed `python3 capture_tdd.py RED test_09_http_envelope`: underlying **exit 1**, 16 assertion failures (15 subcases plus empty-state assertion). Wrong POST paths created/reserved state; malformed JSON/UTF-8 and bad lengths disconnected; missing or invalid keys were not rejected as specified.
3. Implemented exact POST routing, key and content-length validation, body byte bound, and controlled decode/read errors; retained the original transaction and fault harness.
4. Executed `python3 capture_tdd.py GREEN test_09_http_envelope`: underlying **exit 0**.

Evidence: `tdd_logs/test_09_http_envelope-RED.log`, `tdd_logs/test_09_http_envelope-GREEN.log`. Tests cover 15 invalid envelope cases, no persistence, and acceptance of the maximum key length. The raw helper records invalid UTF-8 as a bytes representation so the trace remains valid JSON.

## Complete executable verification

`tdd_logs/full-replay-final.log` captures the latest actual `python3 run_tests.py` run of all nine tests, with `EXIT_CODE=0`. The earlier `tdd_logs/full-replay.log` is retained as well. `report.json` and `trace.jsonl` belong to the final full run, including results/traces for both added slices. The report counts raw validation requests as HTTP operations and explicitly records the suite exit code. Full-run output is captured directly by a subprocess; the report is generated by real tests, not assembled from expected outcomes.

The naive test's overall GREEN means its intentionally broken service was measured violating uniqueness and the expected invariant failure was recorded. It does not mean naive mode became correct. Fault tests use actual sockets, SQLite state, subprocess restart, and SIGKILL, not mocked responses.
